# Пробный сервер и замеры (Ф1): шаг за шагом

Цель: поднять на пробном VPS минимальный сервер, который понимает `netprobe` (вход, `ping`, кадры до 512 КБ, загрузка и скачивание 5 МБ), и прогнать замеры с мобильных сетей. mase переносить не нужно. Всё ниже, кроме шагов 1–2, выполняется после регистрации; регистрацию и оплату делает владелец.

**Проверено в разработке:** тесты `tools/netprobe` (включая `probeserver`), полный прогон `netprobe` против `probeserver` локально, проверки аргументов и `DRY_RUN` обоих скриптов. **Не проверено:** сами скрипты на настоящей ОС с systemd/ufw/sshd (в среде разработки нет ни контейнеров, ни `caddy`), Caddyfile (его проверяет `caddy validate` прямо на сервере до установки), выпуск сертификата из РФ. Первый запуск на сервере — это и есть испытание; держите открытой консоль в панели провайдера на случай ошибки в настройке SSH.

## Домен или IP с самоподписанным сертификатом?

**Нужен домен**, IP не хватит для честного замера. Причины: (1) у боевого сервера будет домен и SNI в TLS-рукопожатии, а ТСПУ может реагировать именно на SNI и IP; при подключении по IP без SNI вы измерите другой путь; (2) с настоящим сертификатом (Let's Encrypt через Caddy) `netprobe` проверяет TLS так же, как приложение; (3) IP-режим требует `netprobe -insecure`, то есть замер без проверки сертификата.

Достаточно поддомена: запись **A** `probe.nemilk.ru` → IP сервера с выключенным проксированием («DNS only», серое облако) в Cloudflare, где сейчас живёт зона. Второй пробный сервер — `probe2.nemilk.ru`. Если зоной управляете не вы, подойдёт любой поддомен любого вашего домена. Ограничение: выпуск сертификата требует, чтобы порты 80 и 443 сервера были доступны из интернета, а Let's Encrypt был доступен с сервера; **из российского VPS это я не проверяла**. Если не выпустился (`journalctl -u caddy -n 50`) — запасной вариант IP-режим (`--ip`, `netprobe -insecure`), но помните про замечание выше.

## 1. Заказ серверов (владелец)

- **Selectel VDS 1-2-25** (250 ₽, почасовая оплата): Ubuntu 24.04 или Debian 12, при создании добавьте свой публичный SSH-ключ. Уточните на странице тарифа, входит ли IPv4 в цену. Пока сервер существует, он оплачивается, даже выключенный: после замеров **удалите** его (шаг 9), если не оставляете как боевой.
- **AdminVPS Lite** (299 ₽, 7 дней бесплатно): Ubuntu 24.04 или Debian 12, ключ или пароль root.

Запишите IP каждого сервера.

## 2. Сборка на своей машине (в этом репозитории)

```bash
cd ~/code/mase/tools/netprobe
export PATH=$PATH:$HOME/go/bin GOPATH=$HOME/go-workspace GOFLAGS=-mod=mod GOPROXY=off
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -trimpath -ldflags "-s -w" -o /tmp/probeserver ./probeserver
go build -o netprobe .            # замерщик для этого компьютера
```

## 3. Первичная настройка сервера

```bash
SRV=<IP-сервера>
scp ~/code/mase/ops/vps-bootstrap.sh ~/code/mase/ops/probe/install-probe.sh ~/code/mase/ops/probe/probeserver.service ~/.ssh/id_ed25519.pub /tmp/probeserver root@$SRV:/root/
ssh root@$SRV 'SSH_PUBKEY_FILE=/root/id_ed25519.pub bash /root/vps-bootstrap.sh'
```

Скрипт: создаёт администратора `admin` с вашим ключом и sudo, включает ufw (22, 80, 443/tcp; UDP 443 закрыт — HTTP/3 не используется), fail2ban, автообновления безопасности, ставит Caddy из репозитория системы (`CADDY_REPO=official` — из репозитория Caddy), создаёт swap, если RAM < 1,5 ГБ, ограничивает журнал 200 МБ и **последним шагом** запрещает вход по паролю. Go на сервер не ставится (собираем у себя). Перед запуском на сервере можно посмотреть план: `DRY_RUN=1 SSH_PUBKEY_FILE=… bash vps-bootstrap.sh`.

**Не закрывая root-сессию**, в другом окне:

```bash
ssh admin@$SRV 'sudo -n true && echo sudo-ok'
```

## 4. DNS

Создайте запись `probe.nemilk.ru` A → `$SRV` в режиме «DNS only», затем:

```bash
dig +short probe.nemilk.ru        # должен показать IP сервера, а не адреса Cloudflare
```

## 5. Пробный сервер и TLS

```bash
ssh admin@$SRV 'sudo bash /root/install-probe.sh --domain probe.nemilk.ru --bin /root/probeserver'
# запасной вариант без домена:  --ip $SRV   (потом netprobe -insecure)
# эксперимент TLS 1.2:          добавить --tls12
```

(Файлы лежат в `/root`, у `admin` к ним доступа нет: либо выполните шаг от root — `ssh root@$SRV 'bash /root/install-probe.sh …'` — либо сначала `sudo mv`. Проще от root, пока root-вход по ключу разрешён.)

Скрипт создаёт пользователя `mase`, кладёт бинарь в `/usr/local/bin`, пишет пароль пробного аккаунта в `/etc/mase-probe/env` (телефон `+70000000099`), включает systemd-юнит `mase-probeserver`, проверяет Caddyfile командой `caddy validate` до установки и ждёт выпуска сертификата. Пароль забрать:

```bash
ssh admin@$SRV 'sudo cat /etc/mase-probe/env'      # положить пароль в менеджер паролей, в чат и в git не класть
```

Проверка из дома:

```bash
curl -sS https://probe.nemilk.ru/health ; echo
export MASE_PROBE_PHONE=+70000000099
read -rsp 'пароль probe: ' MASE_PROBE_PASSWORD; export MASE_PROBE_PASSWORD
~/code/mase/tools/netprobe/netprobe -url wss://probe.nemilk.ru/ws -label "дом-проверка" -hold 0
```

Все шаги должны быть `ok`. Если нет, диагностика: `ssh admin@$SRV 'sudo journalctl -u caddy -u mase-probeserver -n 60 --no-pager'`.

## 6. Замер с мобильной сети

Самый простой вариант — ноутбук через телефон-хотспот (USB-модем или Wi-Fi) нужного оператора; **домашний Wi-Fi и VPN выключены**, экран телефона не гасить (иначе хотспот заснёт во время 30-минутного удержания). Проверьте, что вы действительно в сети оператора:

```bash
nmcli radio wifi off 2>/dev/null; ip route | head -3
curl -s -m 10 https://ifconfig.me ; echo               # внешний адрес
curl -s -m 10 https://ipinfo.io/org ; echo             # оператор по ASN, если сайт доступен
```

Замер (из корня репозитория; `pipefail` сохраняет код возврата за `tee`):

```bash
cd ~/code/mase
export MASE_PROBE_PHONE=+70000000099
read -rsp 'пароль probe: ' MASE_PROBE_PASSWORD; export MASE_PROBE_PASSWORD
mkdir -p docs/reachability-runs
set -o pipefail
LABEL="мтс-мобильный-selectel"        # оператор-тип-сервер, без пробелов
./tools/netprobe/netprobe -url wss://probe.nemilk.ru/ws -label "$LABEL" 2>&1 \
  | tee "docs/reachability-runs/$(date +%F_%H%M)-$LABEL.txt"
echo "код возврата netprobe: ${PIPESTATUS[0]}"
```

Один прогон занимает ≈ 31 минуту (30 минут удержания). Для быстрой проверки добавьте `-hold 0` (≈ 10 секунд): сначала быстрый прогон у каждого оператора, потом полный. Повторите для трёх операторов (МТС, МегаФон, Билайн/Теле2) и для второго сервера (`probe2.nemilk.ru`, метка `…-adminvps`).

Пробный аккаунт один на сервер: два прогона одновременно с одним паролем допустимы (пробный сервер принимает до 8 соединений), но замеряйте по одному, чтобы не мешали друг другу.

## 7. Эксперимент TLS 1.2 (только если были обрывы)

```bash
ssh root@$SRV 'bash /root/install-probe.sh --domain probe.nemilk.ru --bin /root/probeserver --tls12'
# повторить замер с меткой …-tls12; вернуть обычный режим — тот же запуск без --tls12
```

Это проверка гипотезы из раздела 4.1 карты (блог eByeBots), не установленный факт.

## 8. Записать результаты

Строку на каждый прогон занести в `docs/reachability.md` по файлу из `docs/reachability-runs/`, файлы закоммитить (в них нет паролей и токенов).

## 9. После замеров

- **Selectel:** удалить сервер в панели, если он не станет боевым (оплата почасовая, выключенный сервер тоже оплачивается).
- **AdminVPS:** пробный период кончится сам; если не берёте, отмените заказ.
- Удалить запись DNS `probe*.nemilk.ru` (или оставить для боевого сервера).
- Пробный аккаунт живёт только на пробном сервере и с ним исчезает.

## Не покрыто

Нагрузочная проба на самом тарифе (три параллельные загрузки по 50 МБ, 15 сокетов, 15 входов подряд, раздел Ф1 карты) этими средствами **не делается**: `probeserver` хранит файлы в памяти и ограничен 8 МБ, так что он не покажет ни лимит CPU, ни память под реальный mase. Это отдельная задача после выбора провайдера, на реальном mase-сервере.
