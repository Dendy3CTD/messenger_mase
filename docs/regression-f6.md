# Регрессионные сценарии для Фазы 6 (и 7)

Дефекты R-11, R-12, R-13 **воспроизведены запуском** на тестовом сервере 2026-09-19.
Исходные скрипты того прогона не сохранились: сценарии ниже записаны по
`docs/PROTOCOL.md` (раздел 7) и коду `handler.go`, **после переноса в Go-тесты их надо
один раз запустить на текущем коде и убедиться, что они красные** (Ф5: «сначала красный тест»).

Общая подготовка: временная БД и медиа-каталог (не `~/mase-data/`), сервер на свободном порту,
три пользователя A, B, C (регистрация через `auth.register`, у каждого свой сокет и токен).
A и B ведут личный чат (`chat.direct.open` / `chat.direct.send`); C — посторонний, онлайн.

| № | Риск | Шаги | Сейчас (дефект) | Ожидаемо после исправления |
|---|---|---|---|---|
| S-1 | R-11 | A шлёт B текст `secret`, получает `messageId`. A шлёт `chat.message.edit` (`body:"new secret"`). | C получает `evt.message.edited` с новым текстом | C не получает ничего; A и B получают событие |
| S-2 | R-11 | C шлёт `chat.message.edit` с `messageId` сообщения A | A и B получают `evt.message.edited` (БД не изменилась, событие поддельное) | C получает ошибку (`forbidden`); A и B ничего не получают; в БД текст прежний |
| S-3 | R-11 | C шлёт `chat.message.delete` с `messageId` сообщения A | A и B получают `evt.message.deleted` | C получает ошибку; A и B ничего не получают |
| S-4 | R-12 | A шлёт `typing` (`chatId` личного чата A–B, `isTyping:true`) | C получает `evt.typing` | получает только B |
| S-5 | R-12 | C шлёт `typing` с `chatId` чужого чата | A и B получают `evt.typing` от C | ошибка `forbidden`, никто не получает |
| S-6 | R-13 | C шлёт `chat.receipt` с `messageId` сообщения A→B | сообщение в БД `read`; `evt.receipt` уходит A и B | ошибка; статус в БД прежний; событие не рассылается |
| S-7 | R-13 | A шлёт `chat.receipt` для собственного сообщения | сообщение помечено `read` автором | не меняет статус (получатель — B) |
| S-8 | R-15 | Соединение X регистрирует пользователя 1 (`auth.register`), затем на **том же** сокете `auth.login` пользователя 2; X закрывается; новое соединение шлёт `auth.login` пользователя 1 | вход пользователя 1 **не получает ответа** (хаб заблокирован навсегда), `/health` отвечает `ok`; в логе `http: panic serving …: send on closed channel` | вход проходит за < 1 с; закрытое соединение не остаётся в `byUser`; паника в обработчике не оставляет мьютекс захваченным |

Побочные проверки, которые стоит добавить в те же тесты: `group.leave` не участником (R-14),
`chat.history` группы отдаёт `forbidden` (Ф8), второй пользователь с пустым `username` (Ф3).
