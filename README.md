# mase

Мессенджер для Android с собственным сервером: рабочий инструмент проектной группы, замена Telegram.

> **Важно.** Мессенджер работает **через интернет**: приложение подключается по WebSocket (`wss://`) к серверу на Go, устройствам **не нужно находиться в одной сети**. Вход по **номеру телефона и паролю** (SMS-кодов нет, номер не подтверждается). Если вы видели описание «локальный мессенджер на C++, порт 5555, OTP по SMS, mDNS, работает в Wi-Fi без интернета» — это версия 0.2, она устарела и лежит в [`legacy/`](legacy/) без поддержки.

**Состояние: ранняя разработка, версия 0.3.0.** Проект не готов к использованию вне круга разработчика. Что работает и что нет, перечислено ниже; план работ до версии 1.0 — в [`ROADMAP.md`](ROADMAP.md).

## Как это устроено

```
Android-клиент (Kotlin, Jetpack Compose, Room)
        │  WebSocket (JSON), wss://<сервер>/ws
        │  HTTP: загрузка и раздача файлов (/upload, /media/<id>)
        ▼
Go-сервер (gorilla/websocket) + SQLite (режим WAL)
```

- Сервер — `go-server/`, клиент — `android-client/`. Протокол описан в [`docs/PROTOCOL.md`](docs/PROTOCOL.md).
- Приложение собирается в двух вариантах (флейворах): **prod** (боевой сервер по TLS) и **dev** (локальный сервер на вашей машине). Их можно поставить на один телефон рядом.
- Данные (базы, загруженные файлы) **не хранятся в репозитории**: они лежат в `~/mase-data/`; собранные APK — в `dist/` (тоже не в git).

## Что уже есть, а что нет

Оценка получена чтением кода (подробности и ссылки на строки — в `ROADMAP.md`, раздел 2); приложение целиком на устройстве не проверялось.

| Область | Состояние |
|---|---|
| Регистрация, вход по телефону и паролю, сессия по токену | есть (пароли хранятся слабо, это в плане на Фазу 6) |
| Общий чат, личные чаты (текст), контакты, профиль, поиск по username | есть |
| Групповые чаты, правка и удаление сообщений | есть только на сервере, в приложении нет экранов |
| Фото, аватарки | отправка есть; показ, по коду, сломан (приложение просит файл без токена) |
| Доставка при обрывах связи, очередь неотправленного, реконнект | **не работает как нужно** (сообщения могут теряться) |
| Индикатор набора, онлайн-статус, «прочитано» | не работают (несовпадение форматов клиента и сервера) |
| Голосовые, файлы, push-уведомления, поиск по истории, автообновления | нет |
| Тесты, CI, резервные копии | тесты единичные (конфигурация, правила `run.sh`, invite-ссылки); CI и резервных копий нет |

## Требования

- **Go 1.23** и **gcc** (SQLite-драйвер собирается с CGO);
- **JDK 17 или новее** (проверено на 21) и **Android SDK, API 34**; путь к SDK — в `android-client/local.properties` (`sdk.dir=…`, файл не в git);
- `curl` и `ss` (`iproute2`) для `run.sh`;
- для Cloudflare Tunnel в режиме prod — `cloudflared` (см. ниже).

## Разработка (dev)

Запуск локального сервера. Он работает на порту **8081**, использует базу `~/mase-data/dev.sqlite` и **не поднимает туннель**; прод-базу и прод-адрес затронуть не может:

```bash
./go-server/deploy/run.sh dev
```

Сборка приложения:

```bash
./build_apk.sh dev                                       # dev-APK для эмулятора (сервер на 10.0.2.2:8081)
MASE_DEV_HOST=192.168.1.10 ./build_apk.sh install-dev    # собрать и поставить на телефон по USB;
                                                         # адрес — IP машины с сервером в вашей сети
./build_apk.sh                                           # prod debug-APK (боевой адрес)
```

dev-приложение — это отдельное приложение «Mase Dev» (`com.mase.messenger.dev`, схема ссылок `mase-dev://`); ему разрешён незашифрованный трафик (`ws://`), боевому — нет.

Тесты:

```bash
cd go-server && go test ./...                            # тесты сервера
./go-server/deploy/test-run.sh                           # проверки правил run.sh (без запуска сервера)
cd android-client && ./gradlew :app:testDevDebugUnitTest :app:testProdDebugUnitTest
```

## Настройка сервера

Параметры берутся из **явного флага**, иначе из **переменной окружения**, иначе используется значение по умолчанию (флаг всегда сильнее переменной):

| Параметр | Флаг | Переменная | По умолчанию |
|---|---|---|---|
| Адрес | `-addr` | `MASE_ADDR` | `:8080` |
| База SQLite | `-db` | `MASE_DB` | `mase.sqlite` |
| Каталог файлов | `-media` | `MASE_MEDIA` | `./media` |
| Уровень логов | `-log-level` | `MASE_LOG_LEVEL` | `info` (пока только проверяется, фильтрация — в плане) |

`./go-server/deploy/run.sh` сам задаёт эти параметры для каждого режима. Напрямую сервер запускается так: `cd go-server && go run ./cmd/server -db /tmp/test.sqlite -addr :9000`.

## Боевой запуск (prod)

Только для владельца проекта. Режим поднимает публичный Cloudflare Tunnel к боевому домену, поэтому защищён от случайного запуска: нужны явный путь к **существующей** базе, подтверждение `MASE_I_MEAN_PROD=1` **в той же команде** (не экспортируйте её в окружение) и интерактивный терминал. Скрипты, тесты и автоматика прод запустить не могут.

```bash
MASE_I_MEAN_PROD=1 MASE_DB=~/mase-data/mase.sqlite ./go-server/deploy/run.sh prod
```

Без `MASE_DB`, с несуществующим файлом базы (обход — `MASE_ALLOW_NEW_DB=1`) или без терминала скрипт не стартует. Что делать, если туннель поднялся случайно, описано в [`RUNBOOK.md`](RUNBOOK.md).

## Структура репозитория

```
mase/
├── go-server/
│   ├── cmd/server/          точка входа
│   ├── internal/
│   │   ├── auth/            пароли (хеш), токены
│   │   ├── config/          флаги, переменные окружения, значения по умолчанию
│   │   ├── db/              схема SQLite и запросы
│   │   ├── handler/         обработчики сообщений WebSocket
│   │   ├── hub/             подключения и рассылка
│   │   ├── media/           загрузка и раздача файлов
│   │   └── push/            заглушка push-уведомлений
│   └── deploy/              run.sh (dev/prod), test-run.sh, конфигурация туннеля
├── android-client/
│   └── app/src/
│       ├── main/            код приложения (data, invite, media, messaging, network, ui)
│       ├── dev/, prod/      различия флейворов (имя, сетевая политика)
│       └── test/            модульные тесты
├── docs/PROTOCOL.md         описание протокола WebSocket и HTTP
├── legacy/                  версия 0.2 (C++, TCP, mDNS): не поддерживается
├── build_apk.sh             сборка APK (prod, dev, установка на телефон)
├── ROADMAP.md               план до версии 1.0, аудит, риски
└── RUNBOOK.md               инструкции на случай инцидентов
```
